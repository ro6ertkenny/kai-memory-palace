# 🧪 Execution Drills — README (LFCS)

**Path:** `linux/LFCS-training/execution-drills/`

Mental mode: **Mechanical execution, muscle memory, speed**  
Purpose: Turn **common Linux operations into reflexes** so your brain is free for **diagnosis and decision-making** during the exam.

---

## 🎯 What This Directory Is

This directory contains **execution-first training drills**.

Each file is:

- A **repeatable lab**
- A **command execution checklist**
- A **muscle-memory builder**
- Focused on **what to type**, not long explanations

If a task can be solved by:

> **Typing the right commands in the right order**

…it belongs here.

These drills exist to eliminate:

- Hesitation
- Syntax recall
- “What was that command again?” moments

---

## 🚫 What This Directory Is NOT

These files are **not**:

- Tutorials
- Explanations of theory
- Conceptual lessons
- Troubleshooting guides

Those live elsewhere:

- Concepts → Building Blocks
- Diagnosis → Failure Scenarios
- Recovery algorithms → Execution Playbooks

---

## 🧠 How This Fits Into the LFCS Training System

Your training system has **four layers**:

### 1) Building Blocks (Training Progression)

> “What mental models and skills must I master?”

These define:
- Gates
- Required capabilities
- When you’re allowed to move forward

---

### 2) Execution Drills (This Directory)

> “Can I execute the basics **without thinking**?”

These build:
- Speed
- Accuracy
- Mechanical confidence

They remove **typing and syntax** from the list of things that can slow you down.

---

### 3) Execution Playbooks

> “Given a class of problem, what is the **correct algorithm**?”

These are:
- Domain recovery procedures
- Step-by-step **decision flows**
- Used during real troubleshooting and failure scenarios

---

### 4) Failure Scenarios

> “Given a broken system, can I **classify, choose the right playbook, and recover**?”

These test:
- Diagnosis
- Judgment
- Flow control under pressure

---

## 🔁 The Core Training Loop

Execution drills exist to support this loop:

> **Stabilize → Identify → Execute → Verify**

If you are slow at **Execute**, you will:

- Panic
- Waste time
- Lose points on the exam

These drills make **Execute automatic**.

---

## 🧭 How To Use This Directory

### The non-negotiable rules

- **Type the commands**
- Do **not** copy/paste
- Always:
  - Inspect
  - Act
  - Verify

### The workflow

1) Pick one drill file  
2) Run it **top to bottom**  
3) Type every command  
4) Verify every result  
5) If something breaks:
   - Fix it
   - Understand why
   - Continue
6) Reset and repeat

---

## 🏋️ Training Modes

### Daily reps

- Pick 1–2 drills
- Run them end-to-end
- Goal: **zero hesitation**

### Weakness targeting

- When a failure scenario exposes a weakness:
  - Come back here
  - Drill that exact file

### Mock exam warmup

- Randomly pick 2–3 drills
- Do them cold
- No notes
- No lookup

---

## ✅ What “Good” Looks Like

You are “done” with a drill when:

- You do not pause to remember commands
- You do not second-guess syntax
- You do not need to look anything up
- You naturally:
  - inspect first
  - verify after

---

## ⚠️ Why This Matters For LFCS

The LFCS exam is:

- Time constrained
- State-based
- Unforgiving of:
  - Hesitation
  - Wrong commands
  - Slow typing + thinking combined

Your **thinking time** must be spent on:

- Reading the task
- Classifying the problem
- Choosing the right playbook

Not on:

- Remembering how to mount a filesystem
- Remembering how to inspect a service
- Remembering how to query a package
